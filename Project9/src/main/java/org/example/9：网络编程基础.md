## 任务一：初识网络编程

首先必须要清楚：

两者处于网络通信的不同抽象层级：SocketChannel 是传输层（TCP）的字节流通道，而 HttpURLConnection 是应用层（HTTP）的协议客户端。

联系：HttpURLConnection类的底层本质也是通过SocketChannel的代码实现的，只是对Http协议进行了封装，省去了自己手写请求行、解析状态码的过程。

区别：

|          | HttpURLConnection                  | SocketChannel                      |
| -------- | ---------------------------------- | ---------------------------------- |
| 抽象层级 | 应用层。进行了封装。               | 传输层。直接面向字节流。           |
| 协议支持 | 由于封装关系，仅支持HTTP/1.1       | 可用来承载任何协议（但要自己实现） |
| 阻塞模型 | 完全阻塞                           | 支持非阻塞（好像要配合Selector）   |
| 连接复用 | 有限复用                           | 支持长连接                         |
| 主要用途 | 自定义私有协议、需要极低延迟的场景 | 遗留系统维护                       |

至于现代后端为何不再用HTTPURLConnection:

1.API设计陈旧，体验感差：具体来说，就是你连发送一个Header都要用多行代码来实现，且很容易写错。

2.是一个阻塞模型：现代后端通常需要用到非阻塞的异步调用来支撑大型数据传输，而它不可能做到

### 责任链模式

修改后的代码如下：

```
package org.example;

import com.alibaba.fastjson2.JSON;
import okhttp3.*;

import java.io.IOException;



public class UserManager{
    public static final OkHttpClient  client1= new OkHttpClient.Builder().addInterceptor(new Interceptor() {
        @Override
        public Response intercept(Chain chain) throws IOException {
            Request request = chain.request().newBuilder()
                    .addHeader("Authorization", auth)
                    .build();
            
            return chain.proceed(request);
        }
                                                                                         }
    ).build();

    private static final String host = "https://test.glimmer.org.cn";
    private static final String auth = "Bearer glimmer_recruit";
    private static final OkHttpClient client = new OkHttpClient();
    public record User(long id, String nickname) {}

    // 新增用户
    public static boolean addUser(User user) {
        Request request = new Request.Builder()
                .url(host + "/users")
                .post(RequestBody.create(JSON.toJSONString(user), MediaType.get("application/json")))
                .build();
        return execute(request);
    }

    // 删除目标id对应的用户
    public static boolean removeUser(long id) {
        Request request = new Request.Builder()
                .url(host + "/users/" + id)
                .delete()
                .build();
        return execute(request);
    }

    // 更新目标用户的信息
    public static boolean updateUser(User user) {
        Request request = new Request.Builder()
                .url(host + "/users/" + user.id)
                .put(RequestBody.create(JSON.toJSONString(user), MediaType.get("application/json")))
                .build();
        return execute(request);
    }

    // 根据id查询对应的用户
    public static User getUser(long id) {
        Request request = new Request.Builder()
                .url(host + "/users/" + id)
                .get()
                .build();
        try (Response res = client.newCall(request).execute()) {
            if (res.isSuccessful()) {
                ResponseBody body = res.body();
                if (body != null) return JSON.parseObject(body.string(), User.class);
            }
        } catch (IOException e) {
            System.err.println("请求出现异常，请检查网络可达性");
        }
        return null;
    }

    // 简单提取重复代码，用于发送请求，并返回是否成功
    private static boolean execute(Request request) {
        try (Response res = client.newCall(request).execute()) {
            return res.isSuccessful();
        } catch (IOException e) {
            System.err.println("请求出现异常，请检查网络可达性");
        }
        return false;
    }
}
```

使用链式编程为客户端的构建添加拦截器，并使用addheader统一添加请求头（但后面的每个方法中用到的客户端对象都必须使用一开始new出来的）
